写给 agent 消费的任何文档的参考：一个 skill、一份 `AGENTS.md` / `CLAUDE.md`、一份通过指针到达的文档。
**打包方式不同，写法相同**：同一批杠杆让每一份都可预测，
因为 agent **每次跑的是同一个过程**，而不是产出同样的输出。

你写的东西是 skill 时，另外读上游 `SKILL-MECHANICS.md` 了解 frontmatter、调用方式的选择，以及路由型 skill。

## 上下文指针（Context pointers）

**上下文指针**是握在 agent 上下文里的一个引用，
它点名某份不在上下文里的材料，并**编码了到达它的条件**。
一个 skill 的 description 就是一个指针；
`AGENTS.md` 里点名某份文档的一行也是同一个东西。
**决定 agent 何时到达该材料、以及可靠性有多高的，是指针的措辞，不是它的目标。**
一个必须被到达的目标配上一句措辞孱弱的指针，就是一个**变异性 bug**：
**先把措辞磨锋利，只有磨不动了才把材料内联进来。**

指针干两件事：说清材料是什么，以及列出应该触发到达它的那些**分支**
（一个分支是这份文档处理的一个独立情况，所以不同的运行会走不同的路径穿过它）。
**一个总是被加载的指针，每个字在每一轮都在收费**，所以它比正文更该被狠狠修剪：

- **把领头词前置**：指针是指挥它自己触发的地方。
- **一个分支一个触发词。** 重命名同一个分支的同义词，就是一个分支写了两遍；
  合并它们，只留真正不同的分支。
- **砍掉正文已经承载的身份信息。**

## 两种负载

你加的每一份文档和指针，都在花两种预算之一：

- **上下文负载（Context load）**是常驻材料在 agent 窗口上的开销：
  `AGENTS.md` 的一行、一个 skill description、任何每一轮都待在上下文里的东西，
  不管触发不触发都在花 token 和注意力。
- **认知负载（Cognitive load）**是在**人**身上的开销：有哪些文档、什么时候该去拿哪一份。
  **人是那个索引。** 这不是要最小化的成本：**它是人类主体性的代价**；
  花在人类判断重要的地方，不重要的地方就去掉。

只能通过指针到达的材料，用指针自己那一行的代价换来了免于上下文负载；
**完全没有指针的材料，就整个骑在认知负载上。**

## 信息层级

一份文档由两种内容构成：**步骤**（agent 执行的有序动作）和**参考**（按需查阅的定义、规则、事实）。
两者自由混合：全是步骤（一份菜谱）、全是参考（一篇评审的规则、本 skill），或者两者都有。
**核心决策是每一块落在信息层级的哪一级**，这是一把按"agent 多急需这份材料"排序的梯子：

1. **文件内步骤**是主层级：agent 做什么，按顺序。
2. **文件内参考**按需查阅。常常是一个**合法的扁平同级集合**（一篇评审的每条规则都在同一级），
   这是个好安排，不是坏味道。
3. **被披露的参考（Disclosed reference）**被推到单独的文件里，通过上下文指针到达，
   只有指针触发时才加载。跨度从同目录的兄弟文件，到活在任何地方、任何文档都能指向的完全外部参考。

**往下推得太少，顶部就臃肿；推得太多，你就把 agent 真正需要的材料藏起来了。这个张力就是全部决策。**

**渐进式披露（Progressive disclosure）**就是沿梯子往下走（从主文件里出来、藏到指针后面），
好让顶部保持可读。**它主要不是 token 优化：它是保护层级结构的方式。**
**分支是判定披露的最干净测试**：
**每个分支都需要的东西内联，只有部分分支才能到达的东西推到指针后面。**
文档有步骤时，本该被披露的文件内参考会把步骤埋掉，
让"关注步骤"变成抛硬币：**这是变异性杠杆，不只是可读性杠杆。**

**同处一地（Co-location）**是文件内的配套动作：
梯子决定一块材料**放多低**，同处一地决定它一旦放下去**旁边坐着谁**。
把同一个概念的**定义、规则、注意事项放在一个标题下**，而不是散落各处，
这样读其中一部分就会把邻居一起带过来。
测试标准：**这份文档读起来应该像为 agent 写的文档。** 成组的材料读起来是这样；散落的不是。
（跟重复区分开：重复是把**一个含义**写在两个地方；散落是把**一个含义**碎在多个地方。）

**臃肿（Sprawl）**是这里的失败模式：文档就是太长了，即使每一行都活着且独一无二。
注意力在过量中变薄，而每一行多余的都多一个要维持相关性的负担。
解药是那把梯子：**把参考披露到指针后面，按分支或序列拆分**，
让每条路径只带它需要的东西。

## 步骤与完成条件

每个步骤都以一个**完成条件（completion criterion）**结束，即告诉 agent 工作做完了的那个条件。
两个属性让它成为杠杆：

- **清晰度**：agent 分得清做完和没做完吗？
  一个含糊的边界（"达成理解了"）会招来**过早完成（premature completion）**：
  在真正做完之前就结束这一步，注意力滑向"**做完了**"这个状态本身。
  前方可见的后续步骤（**完成后步骤，post-completion steps**）提供拉力；
  完成条件的清晰度提供阻力。按顺序防守：
  **先把边界磨锋利**（局部、便宜）；
  只有当它确实无法消除地模糊**并且**你观察到了那种急躁，
  才通过拆分序列把后面的步骤藏起来。
  **藏只在真实的上下文边界处有效**（一次交接、一次 subagent 派发；内联调用留着后面的步骤，什么也没清掉）。
- **要求强度（Demand）**：它要求多少。
  "每一个被修改的 model 都有交代"逼出彻底的工作，而"产出一份变更清单"不会。
  要求强度驱动**腿脚功夫（legwork）**（agent 在工作中做的挖掘，
  潜伏在措辞里，而不是写成自己的步骤），而且它**不受步骤约束**：
  "每一条规则都已应用"约束一批扁平参考，就像"每一个步骤都完成"约束一个序列，
  这就是一份全是参考的文档为什么依然能带一条穷尽性标杆。

**最强的完成条件既是可检查的，也是穷尽的。**

## 什么时候该拆

把一份文档拆成两份要花两种负载之一，所以**只有这笔切割挣得回来时才拆**：

- **按序列拆**：把一串步骤拆开，其中那些"完成后步骤"正在引诱 agent 敷衍眼前这一步。
  把它们置于视野之外能驱动当前任务上更多的腿脚功夫。
  **当心反面**：合并序列会让每个步骤的后续步骤暴露给接下来的动作，招来过早完成。
- **按调用方式拆**，skill 专属：见上游 `SKILL-MECHANICS.md`。

## 领头词（Leading words）

**领头词**是一个紧凑的概念，已经活在模型的预训练里，agent 在跑这份文档时用它来思考
（_lesson_、_fog of war_、_tracer bullets_）。
作为一个 token 反复出现、**从不作为句子出现**，它积累出一个分布式定义，
并用最少的 token 锚定一整个行为区域，靠的是**征用模型已经具备的先验**。
自己造一个也行——只要你定义清楚；但**自造词征用不到任何先验**：
你在定义上花的 token，正是预训练词白送你的，所以**先去找已有的词**。

它锚两次。
在正文里锚**执行**：这个词一出现，agent 每次都伸手去拿同一套行为；
而在扁平参考里，它把注意力聚焦到**要去找的那一类东西**上。
在指针里锚**调用**：当同一个词同时活在你的提示词、你的文档和你的代码库里，
agent 会把这份共享语言和那份材料连起来，更可靠地到达它。

**去找用领头词重构的机会。**
三处地方各自拼写出来的一组三连词；一个指针花一整句去指一个想法。每一处都在求着被收进一个 token：

- "fast, deterministic, low-overhead" → _tight_（一个 _tight_ loop）。
- "a loop you believe in" → _red_，把一个模糊的门变成二进制可观察的状态
  （这个 loop 在这个 bug 上变 _red_，或者不变）。

**你赢两次**：token 更少，而且给 agent 挂思考的钩子更锋利。
**假设每一份文档都在搬运一些能被领头词退役掉的重述。去把它们找出来。**

**否定（Negation）**是这条杠杆旁边的失败模式：
**靠禁止来引导，会把被禁的行为拖进上下文，让它变得更可得，而不是更不可得。**
_别想大象_，然后满脑子都是大象；否定是一个弱修饰词，被强激活的概念压过去了，
于是那条禁令有一半读起来像在指示你去做那件事。
**提示正向的**：说出目标行为（"写一行注释"），被禁的那个就从未被说出口。
只有当你无法正向表述一条硬护栏时，禁令才挣得它的位置；
即便如此，也要配上正向目标，让注意力落在该做什么上。

## 修剪

- **每个含义只留一个真相来源**：一个权威的位置，这样改行为就是改一处。
  **重复**（同一个含义出现在不止一处）花维护成本和 token，
  并且把一个含义在梯子上的显眼程度抬过了它真实的层级。
  （这是领头词意外的反面：领头词**故意**重复一个 token，**从不**重复那个含义。）
- **环境**也是一个真相来源（`package.json` 脚本、配置文件、目录布局、`--help` 输出），
  而一份重述它的文档就是一个**缓存**：一次查找的副本，只有查找很贵时才挣得它的负载。
  **缓存 agent 靠看找不到的东西**：没写下来的约定、某个选择背后的理由、任何配置都不肯承认的坑。
  **把"一个文件、一条命令"的查找留给环境**，在那里它们不会过期。
- **逐行检查相关性**：它还在影响这份文档要做的事吗？
  一行会因为**从不影响任务**（纯铺陈，或者一个本该被披露的分支）
  或因为**随着它描述的行为或世界变化而过期**而丧失相关性。
  **更短的文档更容易保持相关。** 没有修剪纪律，默认命运是**沉积（sediment）**：
  过期的层沉积下来，因为"加"感觉安全、"删"感觉冒险，直到你必须钻开它们才能找到还活着的部分。
- **逐句猎捕无效句（no-ops）**：模型默认就会遵守的指令，花了负载却什么也没说。
  测试（改不改行为，相对于默认？）**是模型相对的，不是读者相对的**：
  两个人对某个 no-op 看法不同，其实是他们对默认值的看法不同，
  而这要靠**跑这份文档**来判定，不是靠辩论。
  一句话没通过测试，就**删掉整个句子**，而不是从里面抠掉几个词。
  这个测试也用来给领头词评分：一个弱到打不过默认值的词
  （agent 本来就还算彻底的时候说 _be thorough_）是个 no-op，
  **修法是换个更强的词**（_relentless_），**不是换个技术**。

> **译者注**：如果你只读一个 skill 的正文，读这个。
>
> 它是**元 skill**——其他所有 skill 的写法都建立在它上面。
> 而且它是这里唯一以"**模型怎么读**"为第一性原理展开的：
>
> 三个最反直觉、也最立即可用的点：
>
> **1. 否定会让行为更可得。** 写"不要 mock 内部协作者"，
> 等于把"mock 内部协作者"这个概念强激活在上下文里。
> 改成"只在系统边界上 mock"——被禁的行为从未被说出口。
> 你可以在 [tdd](/cn-aihero-dev/skills/engineering/tdd/) 里看到这条被实际应用。
>
> **2. 领头词是最省 token 的杠杆。**
> 与其在三个地方分别解释"快、确定、开销低"，
> 不如让它一次叫 _tight_，之后每次只说一个词。
> 注意 [diagnosing-bugs](/cn-aihero-dev/skills/engineering/diagnosing-bugs/) 里
> "**能变红的环**"就是这个手法：`red` 一个词把"能抓住这个具体 bug"整片语义锚住了。
>
> **3. no-op 测试是模型相对的。** "要彻底"这种话，
> 模型默认就在做，所以它花了 token 等于没说。
> 判断标准不是"人读了觉得有没有道理"，而是"**它改不改模型的默认行为**"。
> 这一条能删掉你 `AGENTS.md` 里一半的话。
>
> 还有 **沉积（sediment）** 那个比喻值得记住：
> 文档不会变乱，只会**一层层沉积**，因为加总是感觉安全、删总觉得可惜。
