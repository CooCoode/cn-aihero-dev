一个松散的念头来了，太大，一个 agent 会话装不下，而且裹在雾里：
从这里到**目的地**的路还看不见。
**寻路是找到那条路，不是冲向目的地。**
本 skill 把这条路绘制成仓库 issue tracker 上的**共享地图**，
然后一次解一个**决策工单**（答案是决策的工单，不是待执行的构建切片），直到路线清晰。

**目的地每次都不一样，而给它命名是绘图的第一件事**：它塑造每一张工单。
它可能是一份要交接并迭代的规格、一个要在规划开始前锁定的决策，
或者一个原地进行的改动（比如数据结构迁移）。
**地图与领域无关**：工程工作、课程内容，任何符合这个形状的东西都行。

## 规划，不要动手

**wayfinder 默认是规划**：每张工单解一个决策，
地图完成的标准是"路清晰了、在有人去做那件事之前已经没什么要决定的"。
**想直接动手做事的冲动，通常就是"你已经走到地图边缘、该交接了"的信号。**
一次行动可以在它的 **Notes** 里覆盖这条，把执行也纳入地图本身；
但没有这条覆盖，就**产出决策，不产出交付物**。

## 用名字指代

每张地图和每张工单都是一个 issue，所以它有一个**名字**：它的标题。
在人读到的一切里（叙述、地图的 Decisions-so-far），**用名字指代它**，
绝不用裸的 id、编号或 slug。
**一墙的 `#42, #43, #44` 是无法阅读的；名字一眼就看懂。**
id 和 URL 不会消失；名字包着它的链接，但链接是骑在名字**里面**的，从不替代它。

## 地图

地图是这个仓库 issue tracker 上的**单个 issue**，标签 `wayfinder:map`，是那个规范产物。
它的工单是地图的子 issue。

**地图是索引，不是仓库。**
它列出已做出的决策，并指向持有其细节的工单；
**一个决策只住在一个地方——它的工单里**，
所以地图从不重述它，只给要点并链接。

**地图、它的子工单、阻塞、前沿查询具体住在哪，是 tracker 相关的。**
issue tracker 应该已经给你配好了。没有的话，让用户跑 `/setup-matt-pocock-skills`。
查 tracker 文档的 "Wayfinding operations" 一节看**这个**仓库怎么表达它们。
没有配任何 tracker 就默认用本地 markdown tracker。

### 地图正文

整张地图的低分辨率视图，每个会话加载一次。
**未关闭的工单不列在这里**：它们是未关闭的子 issue，靠查询找到。

```markdown
## 目的地

<走到这张地图的尽头是什么样子：这次行动要寻路到达的规格、决策或改动。
一到两行；每个会话先对齐它，再挑工单。>

## 备注

<领域；每个会话都该查阅的 skill；这次行动的固定偏好>

## 目前已做的决策

<!-- 索引：每个已关闭工单一行，够判断相关性就行，细节靠点开链接看工单 -->

- [<已关闭工单标题>](链接): <答案的一行要点>

## 尚未规定

<!-- 见「战争迷雾」：范围内但还开不出工单的迷雾；随前沿推进而毕业 -->

## 范围之外

<!-- 见「范围之外」：被判定在目的地之外的工作；已关闭，永不毕业 -->
```

### 工单

每张工单是地图的**子 issue**；tracker 的 issue id 就是它的身份。
它的正文就是那个问题，大小按**一个 10 万 token 的 agent 会话**来定：

```markdown
## 问题

<这张工单要解决的决策或调查>
```

每张工单带一个 `wayfinder:<类型>` 标签，取值 `research`、`prototype`、`grilling`、`task` 之一。

一个会话**认领（claim）**工单的方式是把它 assign 给驱动这张地图的开发者，
**而且要在做任何工作之前**，这样并发的会话会跳过它。
那个 assignee **就是**认领本身：开着但未 assign 的工单就是无主的。

**阻塞使用 tracker 的原生依赖关系**：这一点是必需的，
因为它把前沿在 tracker 自己的 UI 里**可视化**出来，
于是人不用打开地图就能看见哪些可以领。
只有缺少原生阻塞的 tracker 才退回正文约定。
一张工单在**所有**阻塞它的工单都关闭时是**已解锁**的；
**前沿**就是那些开着、已解锁、无主的子工单——已知世界的边缘。

**答案不属于正文**；它在解决时被记录（见「推进地图」）。
解决工单期间产生的资产从 issue 链过去，不要粘进来。

## 工单类型

每张工单要么是 **HITL**（人在回路，**跟一个能自己说话的人一起**做），
要么是 **AFK**（agent 独自驱动）。
**一张 HITL 工单只能通过那次实时交流解决**；
**agent 绝不代替人的那一侧**（一个自己回答自己问题的盘问 agent 已经破坏了这个原则）。

- **Research**（AFK）：读文档、第三方 API 或本地知识库之类的资源，
  把一个决策所等待的**事实**挖出来。由调用 `research` skill 的 subagent 解决。
  需要的知识在当前工作目录之外时使用。
- **Prototype**（HITL）：通过做一个**便宜、粗糙、具体**的东西来提升讨论的保真度
  （一个提纲、一版粗糙的稿子、一个 stub，或者 UI/逻辑代码），
  方法是调用 `prototype` skill。把原型作为资产链上。
  "**该长什么样**"或"**该怎么表现**"是核心问题时使用。
- **Grilling**（HITL）：对话。**默认情况。** 永远调用 `grilling` 和 `domain-modeling` 两个 skill。
- **Task**（HITL 或 AFK）：在一个**决策**能做出来之前必须发生的手工工作：
  没什么可决策、可原型、可调研的，但**讨论被它卡住直到它做完**。
  注册一个服务好判断它的 API、开通访问权限、搬数据好看清它的形状。
  **这是唯一"做"而不"决策"的类型**，它挣得位置靠的是**解锁一个决策**，
  而不是交付目的地。agent 能独自驱动就独自驱动（AFK）；
  否则给人一份精确的检查清单（HITL）。工作做完就解决；
  答案记录做了什么，以及后续工单依赖的任何事实（凭据位置、新 URL、行数）。

## 战争迷雾

**地图是刻意不完整的：不要画你还看不见的东西。**
在活着的工单之外是**战争迷雾（fog of war）**：
你能看出要来了、但还钉不住的决策与调查的模糊身影，
因为**它们挂在还没解决的问题上**。
解决一张工单会清掉它前方的雾，
把现在已经可规定的东西**毕业（graduate）**成新工单，一次一个，
直到通往目的地的路清晰、不再剩任何工单。

地图的 **尚未规定** 一节就是那份模糊身影被写下来的地方：
怀疑有问题的地方、以后再回来看的区域。
它是**朝向目的地**的未发现前沿：这里的一切都在范围内，只是还不够锋利到能开工单。
视野允许多少就写多少、或者写多松散都行；
它同时给协作者当路标，让人读到这次行动往哪走。

**迷雾还是工单？** 测试标准是你**现在**能不能精确陈述这个问题，
**不是**你现在能不能回答它。

- **是工单**：问题已经足够锋利，即使它被阻塞、你现在还动不了。
- **是尚未规定**：你还不能把它说到那么锋利。
  **不要把迷雾预先切成工单大小的块**：它比一张工单粗，
  而且前沿到达时，一片可能毕业成好几张工单，也可能一张都没有。

**尚未规定**排除：已经决定了的（已做的决策）、已经是活工单的、以及范围之外的（下一节）。

## 范围之外

**迷雾永远只朝目的地聚拢。目的地固定了范围**，
所以超出它的工作是**范围之外**：那不是迷雾，也不属于**尚未规定**。
它在地图上有自己的 **范围之外** 一节：你有意识地排除在**这次**行动之外的工作。
**是范围、不是锋利度**，把它放在这里。

范围之外的工作**永不毕业**（前沿停在目的地），
所以只有当目的地被重画时它才会回来，而且是作为一次全新的行动，不是接着做。

**判定某件事在范围之外是一个划定范围的动作，不是路线上的一个步骤。**
当一张已经存在的工单被发现位于目的地之外时
（绘图时范围划错了，或者被某次解决暴露出来），
**关闭它**（关闭的工单毫无歧义地不在前沿上），并在**范围之外**一节留一行：
要点加上为什么在范围之外，链接到那张已关闭的工单。
**它不进「已做的决策」**——那一节记录**实际走过的路**；一个范围边界不是路上的步骤。

## 调用

两种模式。**无论如何，一个会话绝不解超过一张工单**，研究类工单除外。

### 绘制地图

用户带着一个松散念头调用。

1. **给目的地命名。** 调用 `grilling` 和 `domain-modeling`，钉住这张地图要寻路到达什么：
   规格、决策还是改动。**目的地固定范围，所以它先落定。**
2. **画出前沿。** 再盘问一次，**这次是广度优先**：
   在整个空间上扇开，而不是在任何一条线上往深挖，
   把悬而未决的决策和现在就能走的头几步挖出来。
   **如果这次什么雾都没挖出来**（通往目的地的路已经清晰、整段旅程小到一个会话装得下），
   **你不需要地图。停下，问用户想怎么推进。**
3. **创建地图**（标签 `wayfinder:map`）：填好目的地和备注，
   「已做的决策」留空，把雾草拟进**尚未规定**。
4. **把现在能规定的工单**创建成地图的子 issue，
   然后**第二遍**接上阻塞边（issue 得先有 id 才能互相引用）。
   接完之后它们就分成了前沿和被阻塞的两拨；
   你不能规定的都留在雾里：**尚未规定**那一节。
5. **发射研究 subagent。** 给刚创建的每一个 `research` 工单起一个 subagent
   调用 `research` skill 并行解决它，把结论捕获在一个一次性的 `research/<名字>` 分支上，
   并从工单留一个 context pointer 指过去。
6. 停：绘图是一个会话的工作量；它不手解任何工单。

### 推进地图

用户带着一张地图（URL 或编号）调用。
工单是**可选的**：不给的话，**由你挑下一个决策，不是用户挑**。

1. 加载**地图**：低分辨率视图，不是每张工单的正文。
2. 选工单。用户点名了就用它。否则按顺序取第一张前沿工单。
   **认领它**：做任何工作之前先 assign 给自己。
3. 解决它。**按需放大**：随时取任何相关或已关闭工单的完整正文；
   按 `## 备注` 块点名的 skill 去调用。
   拿不准就调用 `grilling` 和 `domain-modeling` 两个 skill。
4. 记录解决：把答案作为**解决评论**发出，**关闭** issue，
   并给地图的「已做的决策」**追加一个 context pointer**。
5. 添加新浮现的工单（先创建再接线）；
   把答案变成可规定的雾**毕业**，每毕业一片就从**尚未规定**里清掉它，
   让它只作为它的新工单存在。
   如果答案暴露出某张工单（这张或别张）在目的地之外，**判定它在范围之外**，
   而不是把它当路线上的东西解掉。
   如果这个决策让地图的其他部分失效，更新或删除那些工单。

用户可能在并行跑已解锁的工单，所以**预期会有其他会话在并发编辑这个 tracker**。

> **译者注**：这个 skill 处理的是一类很特别的任务——
> **大到"你都不知道该问什么"的工作**，比如从零起一个项目。
>
> 它最有用的一条是 **"迷雾还是工单"的判据**：
>
> > 测试标准是你**现在**能不能**精确陈述**这个问题，不是你现在能不能**回答**它。
>
> 这条判据反过来就很致命：很多人在雾里就急着开工单，
> 结果开出一堆题目本身就是错的工单，解完发现跟目的地无关。
>
> 第二条是 **"规划，不要动手"**：
> 它明确说"想直接做事的冲动，就是该交接的信号"。
> wayfinder 产出的是**决策**，地图画完就该把它折进
> [to-spec](/cn-aihero-dev/skills/engineering/to-spec/) 变成可建的计划。
> 从地图直接跳 [implement](/cn-aihero-dev/skills/engineering/implement/)，会把所有关联的细节丢掉。
>
> 第三条是**工单认领要在动工之前**（assign-first），
> 因为并行会话靠这个来避让。这是个很小但很硬的约定。

## 安装

**这是斜杠命令入口，`description` 不建议翻译。**

```yaml
---
name: wayfinder
description: Plan a huge chunk of work (more than one agent session can hold) as a shared map of decision tickets on your issue tracker, and resolve them one at a time until the way to the destination is clear.
disable-model-invocation: true
---
```
